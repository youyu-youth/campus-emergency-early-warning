# 校园突发事件预警平台 · Web 信息架构与交互设计方案

> 状态：已确认（2026-11-08）
> 依据：PRODUCT.md、AGENTS.md
> 范围：本方案只定义信息架构、页面布局、组件划分、关键交互与状态设计，不含视觉规格（颜色/字号等实现细节在设计系统阶段确定）。
> 平台说明：本产品为 **Web 应用**（浏览器访问），"桌面优先"指优先保证大屏浏览器（投影、机房电脑）的布局效果，不做桌面客户端。

## 0. 已确认的产品决策

| 决策 | 结论 |
|---|---|
| 事件并发模型 | **单事件焦点**：一次推演围绕一个主事件展开，衍生情况作为同一事件时间线上的节点 |
| 推演控制方式 | **自动推进 + 关键节点人工确认**：推演按模拟时钟自动进行（可暂停/恢复/调速），在事件定级、任务方案、通知发布等关键决策点暂停等待操作员确认 |
| 一期模拟范围 | 消防警报、学生突发疾病两类事件 |
| 部署形态 | 本地单机使用，无登录（第一期） |

## 1. 设计方向

**结构主张（反模板核心）**：平台的灵魂不是"一堆指标卡片"，而是**一条正在推进的事件处置流**。所有界面围绕同一条"处置时间线主轴"展开——指挥台看概要、工作区看全量、复盘报告做回放。

**布局语法**：不对称工作台（主画布 + 语境侧栏）、时间线、泳道、表格、抽屉详情。
**禁用**：等宽卡片墙、KPI 卡矩阵；卡片只用于真正独立的对象（场景选择、历史报告条目）。

**视觉策略（现代企业级应急指挥中心：专业、严谨、精致）**：

- **深浅混合指挥台**：深石墨色骨架（左侧导航 + 顶部演练状态条）承载指挥中心气质；浅冷灰工作画布保证课堂投影环境下的可读性
- **等级色系**：应急领域通行的四级色——红Ⅰ（重大）/ 橙Ⅱ（较大）/ 黄Ⅲ（一般）/ 蓝Ⅳ（轻微），只用于等级与告警，**永远搭配文字与图标**，不靠颜色单独区分
- **交互主色**：靛青色，用于选中、链接、主按钮
- **字体**：中文系统字体栈为主；时钟、编号、耗时、信号数据用等宽数字体现仪表感
- **密度**：分区紧凑的数据密度，区与区之间留整块呼吸空间
- **签名动作**：贯穿全平台的「处置时间线脊柱」+ 关键节点暂停时升起的「决策坞」

## 2. 信息架构与导航

### 2.1 全局骨架（所有页面共享）

- **左侧导航栏**（220px，可折叠为 64px 图标栏）：产品名 + 常驻「模拟演练」徽标 → 分组菜单 → 底部单机模式标识
- **顶部演练状态条**（48px，全局唯一时钟源）：当前演练徽标 + 所处阶段 + 模拟时钟（等宽跳动）+ 暂停/恢复快捷控制 + 常驻「模拟演练」标识；无演练时显示"空闲 + 一键发起"

### 2.2 导航分组（按核心闭环顺序）

| 分组 | 页面 | 路由 | 职责 |
|---|---|---|---|
| 态势 | 综合指挥台 | `/` | 到达即知全局：有无演练、系统健康、快速入口 |
| 态势 | 事件监测中心 | `/monitoring` | 模拟信号输入流：感知 Agent 如何解读并上报 |
| 推演 | 事件模拟推演 | `/simulation` | 场景配置、种子、启动；运行中的完整控制台 |
| 推演 | **事件详情工作区** | `/command` | 处置主战场（重点设计，见第 3 节） |
| 推演 | 智能体协作调度 | `/agents` | 多智能体编排视图：协作图 + 交接日志 |
| 推演 | 通知发布中心 | `/notifications` | 通知生成、人工确认、模拟分发记录 |
| 复盘 | 事件复盘报告 | `/reports` | 演练列表 → 时间线回放 + 指标 + 改进建议 |

### 2.3 与 AGENTS.md 五页面的对应

总览仪表盘 → 综合指挥台；事件模拟 → 事件模拟推演；应急指挥 → 事件详情工作区；演练记录 + 复盘报告 → 合并为事件复盘报告（列表即记录）；监测、协作调度、通知中心是从闭环环节升格出的独立页面（教学价值：让每个 Agent 的工作可见）。

### 2.4 演练运行期的导航行为

- 顶部状态条出现"进入工作区"一键直达
- 历史演练的工作区以**只读回放模式**打开（`/drills/[id]`）

## 3. 事件详情工作区（重点设计）

桌面浏览器 1440 基准，不对称三区 + 底部决策坞：

```
┌──────────────────────────────────────────────────────────────────┐
│ 事件头带: [模拟演练] [类型图标] 图书馆三层烟雾报警 · EV-2026-001    │
│           ▎等级 Ⅱ 较大 ▎状态: 处置中 ▎(时钟与控制在顶部全局条)      │
├─────────┬──────────────────────────────────────┬─────────────────┤
│ Agent   │  处置时间线（主轴，自动跟随滚动）          │ 任务与记录        │
│ 编队    │  ═══ 阶段带: 感知 ─ 研判 ─ 处置 ─ 通知 ══ │ ┌ 任务列表        │
│         │   14:02 ● 信号上报（监测感知）            │ │ [保安] 疏散引导  │
● 监测感知 │   14:03 ◆ 定级 Ⅱ级 ⚑人工确认 2m10s      │ │   执行中 · 4m    │
◉ 指挥调度 │   14:05 ● 任务派发 保安×2 医务×1         │ │ [医务] 现场急救  │
◐ 处置·保安│   14:07 ● 反馈：东侧楼梯已封锁           │ │   待确认          │
○ 处置·医务│   ▼ 当前时刻                            │ ├ 操作记录(审计)   │
○ 通知发布 │   （节点点击 → 浮层详情：原始输入/        │ │ 14:03 张老师确认 │
○ 复盘评估 │     Agent 决策依据/结构化输出）           │ │ 定级建议          │
├─────────┴──────────────────────────────────────┴─────────────────┤
│ 决策坞（关键节点暂停时升起）                                         │
│ ⚑ 指挥调度建议: 定为 Ⅱ级 · 理由: 烟雾范围+时段人流                  │
│   任务方案表(可改派)   [查看完整依据]  [确认执行] [调整后执行]        │
└──────────────────────────────────────────────────────────────────┘
```

### 3.1 四个区域的职责

- **事件头带**：事件身份（名称、编号、类型）+ 大号等级徽章 + 状态机当前状态。时钟、暂停/倍速等推演控制在顶部全局条，不在此重复
- **左栏 · Agent 编队**（约 280px）：五个 Agent 的差异化行（非统一卡片）——状态灯（待命/工作中/等待输入/异常/完成）、当前动作一句话、最近输出摘要、累计耗时；活跃 Agent 高亮，空闲压暗；异常态显示降级说明与重试
- **中央 · 处置时间线**（弹性主区）：顶部阶段带标注五阶段进度；节点分七类（信号、定级⚑、派发⚑、执行反馈、状态变更、通知⚑、异常/降级），⚑ 为需人工确认的节点并显示确认耗时；一条当前时刻游标自动跟随，可暂停跟随手动回看；**节点点击展开详情浮层：原始输入、Agent 决策依据、结构化输出**（"可解释"原则的落点）
- **右栏 · 任务与记录**（约 360px）：上半为按保安/医务/后勤分组的任务列表（状态：待确认/执行中/已完成/失败，附耗时）；下半为操作记录审计流（所有人工干预与系统关键动作），与时间线联动
- **决策坞**（底部，条件出现）：推演自动暂停在关键节点时升起，展示指挥调度 Agent 的建议与理由，操作员三选一——**确认执行 / 调整后执行**（就地改等级、增删改派任务）**/ 查看完整依据**；确认后坞收起、推演继续；支持键盘快捷键确认，保证课堂演示节奏

### 3.2 回放模式（历史演练）

同一布局，时间线变为可拖动进度条，无决策坞，顶部标识"回放模式"。

## 4. 其余页面布局

### 4.1 综合指挥台 `/`

上区不对称分割：左侧 2/3 为**演练状态主面板**（无演练时是大号开场引导 + 发起按钮；有演练时是当前演练概要：等级、阶段、时钟、进入工作区）；右侧 1/3 为系统态势侧栏（监测信号摘要、五 Agent 集群健康、通知送达统计，三条紧凑小列表）。下区为**演练历史表格**（可排序：时间/场景/等级/评分/状态）。

### 4.2 事件监测中心 `/monitoring`

左右分割：左侧为**实时信号流**（行式列表：时间、来源图标「传感器/摄像头」、位置、类型、置信度、处理状态，顶部筛选条按来源/类型/状态过滤）；右侧为**选中信号详情抽屉**（原始数据等宽展示 → 感知 Agent 提取的位置/类型/证据 → 上报结果及关联事件跳转链接）。顶部一条信号统计带（今日信号、待处理、已生成事件）。空闲时显示"等待推演开始"空态并可查历史信号。

### 4.3 事件模拟推演 `/simulation`

- **空闲态 = 场景配置**：两个大场景选择（消防警报 / 学生突发疾病，横向展开式而非缩略图卡片墙），展开后为参数表单：地点、模拟时段、强度、**随机种子**（默认随机，可固定以复现）、**人工确认节点开关**（默认开启三级确认）；底部启动按钮 + 从历史演练克隆配置
- **运行态 = 控制台**：场景参数只读展示、完整时钟控制（暂停/恢复/倍速/重置——重置需二次确认）、五阶段进度条、终止演练入口（危险操作区，与普通操作分区放置）

### 4.4 智能体协作调度 `/agents`

主视图为**协作关系图**（节点 = 五类 Agent，边 = 交接关系；运行中活跃节点高亮并有流动指示，点击节点 → 右侧详情面板：职责、当前输入/输出、工具权限、最近调用记录、耗时与成功率）；侧栏为**交接日志**（谁→谁、传递内容摘要）。空闲时展示最近一次演练的静态图。Agent 定义只读展示，不提供编辑。

### 4.5 通知发布中心 `/notifications`

主列表（受众「师生/家长」、关联事件、状态「草稿/待确认/已发布·模拟/失败」、送达统计）+ 通知全文预览（模拟公告/短信式排版，**每条通知预览均带显著「模拟演练」水印**）；详情含生成依据与逐对象分发记录。待确认通知与工作区决策坞联动。

### 4.6 事件复盘报告 `/reports`

列表页为演练表格。报告页结构：报告头（演练摘要 + 总评分）→ **指标条**（横向度量带：总时长、发现→上报、定级耗时、任务完成率、资源消耗）→ **时间线回放**（复用工作区时间线组件，只读 + 关键节点标注）→ 问题分析 → 改进建议；**每条结论可溯源**：点击问题跳回时间线对应节点（对应 AGENTS.md"复盘仅基于留存日志"）。导出格式为未决事项，第一版网页内查看。

## 6. 关键交互

1. **发起推演**：选场景 → 配参数与种子 → 启动 → 自动跳转工作区，顶部状态条进入运行态
2. **关键节点确认**：自动暂停 → 决策坞升起 → 确认 / 调整后执行 / 查看依据 → 继续（默认三个确认点：事件定级、任务方案、通知发布；场景配置中可关闭改为全自动）
3. **推演控制**：全局可用——暂停/恢复/倍速/重置（二次确认）/终止
4. **时间线交互**：节点点击看详情、自动跟随/暂停回看、回放模式拖动
5. **信号追踪**：监测中心信号 → 感知解读 → 生成事件，三段可互相跳转
6. **任务干预**：确认阶段就地改派；运行中重新调度由指挥 Agent 发起并经确认点放行
7. **通知确认**：待确认 → 发布（模拟）→ 送达统计更新
8. **复盘溯源**：报告结论 → 点击跳回时间线对应时刻

## 7. 状态与异常清单

| 场景 | 设计 |
|---|---|
| 首次使用/无演练 | 指挥台大空态 + 发起引导；监测中心"等待推演"空态 |
| 加载中 | 骨架屏（不用转圈遮罩盖住整页） |
| 实时数据 | 轮询或实时推送（实现阶段定）；断线时显示"数据可能滞后"横幅并自动重连，不清空已有内容 |
| 等待人工确认 | 状态条阶段标注 + 决策坞 + 时间线⚑节点提示，教学场景不限时等待 |
| 推演暂停/恢复/重置 | 顶部状态条明确状态；重置与终止需二次确认 |
| Agent 超时/失败/输出无效 | 编队行转异常态 + 降级说明 + 重试；时间线记异常节点；不阻塞其他 Agent |
| 通知模拟分发失败 | 状态标"模拟失败"，不影响主线推演 |
| 报告生成 | 生成中进度、失败可重试 |
| 筛选无结果 / 长文本 | 明确空态文案；截断 + 悬停展开 |
| 模拟时间 vs 真实时间 | 两处时钟并列展示并注明来源，日志带时间来源标记 |

## 8. 约束、反目标与未决事项

**硬约束**（来自 AGENTS.md）：技术栈固定（Next.js App Router + TypeScript、Tailwind CSS + shadcn/ui、LangGraph.js + LangChain.js、SQLite 仅服务端）；全中文文案；状态不靠颜色单独区分；**「模拟演练」标识贯穿所有事件、通知与报告**；桌面浏览器优先（1280+ 完整，1024–1279 侧栏折叠为图标栏 + 右栏转标签页，1024 以下纵向堆叠保基础可用）。

**反目标**：等宽卡片墙与 KPI 卡矩阵；游戏化元素；把界面做成真实警情系统的拟真外观；用颜色承载全部状态含义。

**未决事项**：

1. 主题基调：推荐"深骨架 + 浅画布"混合方案；若使用环境以暗环境投影为主，可改纯深色主题
2. 手动注入测试信号是否纳入二期（一期信号全部由模拟引擎按场景生成）
3. 复盘报告导出格式（PRODUCT.md 已记录的未决项）

## 9. 实现路线（已确认顺序）

1. **项目基座**：依赖安装（shadcn/ui、LangChain.js + LangGraph.js、SQLite）、数据库 Schema 与迁移、事件/任务状态机纯函数、演练时钟与模拟引擎骨架（含单元测试）
2. **端到端最小闭环（后端优先）**：五类 Agent 提示词与结构化输出、LangGraph 编排（条件路由、并行处置、关键节点暂停/恢复）、分步执行与进度持久化；验收 = 固定场景 + 模拟模型响应跑通全链路测试
3. **UI 逐页实现**：壳层（导航栏 + 状态条 + 状态语言组件）→ 事件详情工作区 → 综合指挥台 → 事件模拟推演 → 监测/协作/通知 → 复盘报告；每页同步做空态、加载、异常态
4. **收尾**：lint / typecheck / test / build 全过，UI 走查（1280 与窄屏）
